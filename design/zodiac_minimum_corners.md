# 黄道十五星座：正交边界的最少拐点

本文保留历史算法 **`terrax-zodiac-draw-7`** 的方法与验证，旧轮仍可按原配方恢复。当前默认为 [draw-9 与候选窗口编辑](zodiac_candidate_editing.md)，沿用 [draw-8 的亮星与局部优先算法](zodiac_local_first.md)；不继承本版占格最优声明。

draw-7 边界只沿第 0 日参考赤经线、赤纬线，不允许斜边。在其 **1° 网格、固定星形及下述归属约束**下，联合求出十五区的全局最少拐点；达到最少后，再求占格数最少的解。

## “最少”的范围

优化的变量是各个格子的实际归属，十五区一起求解。固定条件如下：

1. **网格与方向。** 使用 360 × 180 的 1° 参考赤经／赤纬网格，赤经在 0°／360° 连续连接。边界由完整格边组成，每段恒赤经或恒赤纬，黄道区域不触及参考极点。
2. **星形与可用空间。** 从根种子的 draw-6 初始适中方案取得十五个参考星形。各区只能使用参考球面凸包周围 8° 内的允许格子；沿用整格保守余量判定，而非只检查顶点。
3. **受保护归属。** 保留全部候选星所在格的归属，包括未命名余区中的候选。保留同一区内原先合法、长度不超过 13° 的候选短大圆连线所经过的格子，以及黄道经过的所有格子。
4. **区域拓扑。** 每个星区为一个连通、无洞、无对角自接触的区域。十五区不能重叠；其余格子归未命名余区，供以后设计其他星座。
5. **优先顺序。** 先最小化十五区拐点数的总和，再在这个总数不变的前提下最小化占格数。公共边界的拐点在各相关星区分别计数；这不是只数整张图上互不重复的交点，也不要求每区分别达到脱离邻区后的最小值。

保护范围略大于当前画出的几条连线，是为了让之后的锁定、局部重抽仍使用同一边界和同一候选池。丰富模式与局部变体继续保留参考凸包的轮廓锚星，因此新边界也受实际成员支持；验证器另检查本轮实际成员凸包的整格余量。

这一结果**不代表任意连续坐标、任意更细网格，或重新选星后的全局最少**。改变网格、可用空间或受保护归属，就形成了另一个优化问题。凸包用于限制向外距离，不要求区域填满整个凸包；必须完整包住的是星形成员和连线。

## 求解方法与依据

实现使用混合整数线性规划（MILP），通过浏览器本地的 HiGHS WebAssembly 求解。模型位于 [minimum_corners.mjs](../web/constellations/minimum_corners.mjs)，星形与版本接入位于 [generator_minimum.mjs](../web/constellations/generator_minimum.mjs)。

### 1. 将归属写成整数变量

令 `x(i,k)` 为二元变量，表示星区 `i` 是否拥有格子 `k`。

- 只为该星区允许占据的格子创建变量。
- 受保护的已有归属固定为 1，其他星区不能占用；受保护余区不能划给十五区。
- 每格满足 `Σᵢ x(i,k) ≤ 1`。全部为 0 即属于未命名余区。
- 固定成员若落在本区允许空间外，直接报错，不将其忽略后继续求解。

### 2. 精确计算拐点

对于一个星区，在每个网格顶点读取四个邻格的二元归属：

`D = x(NW) − x(NE) − x(SW) + x(SE)`

没有对角自接触时，四格全部同属、全部不属，或边界直穿顶点，都有 `D = 0`；凸角与凹角有 `|D| = 1`。棋盘式对角接触有 `|D| = 2`，用 `−1 ≤ D ≤ 1` 排除。

为每个星区的每个相关顶点引入 `0 ≤ c ≤ 1`，约束 `c ≥ D`、`c ≥ −D`。最小化 `Σc` 时，`c` 恰好等于 `|D|`，所以目标函数就是实际拐点数，不是长度、曲率或“看起来更平滑”的替代分数。

### 3. 排除孤岛与孔洞

求出一个整数解后，检查每区及其补集的四邻接连通分量：

- 若有不连接固定根格的星区孤岛，以该孤岛的一格为锚，要求保留锚时必须占据至少一个外围相邻格。
- 若有被星区包住的空洞，以洞内一格为锚，要求填入锚或打开至少一格包围环。

这两类约束都不会删除任何合法的连通无洞解。例如，一个合法区域若保留孤岛中的锚并连接外部固定根，路径必然穿过孤岛的外围环；若保留洞内空白并保持补集连通，路径必然穿过包围环。添加约束后重新优化，直到最优解同时通过拓扑检查。

因此每次模型仍是合法解集合的放宽。当这个放宽模型的最优解本身合法时，其目标值既是下界又是可行值，便是原约束问题的最优值。最多进行 128 轮分离；不能完成就拒绝本次结果。

### 4. 取得最少拐点后，再收紧占格

第一阶段只接受求解器返回 `optimal`，并检查整数目标值及求解下界：下界必须足以排除少一个拐点的整数目标。随后固定 `Σc = 已证最少拐点`，把目标改成 `Σx`，用相同的最优性与拓扑检查再求解。

这使任何占格收益都不能用增加拐点交换。示例最终占 **9,536 格**，是其 186 拐点条件下的最少占格数；格子随赤纬有不同球面面积，所以这不是“最小球面面积”的证明。最少拐点优先也不保证每一个单区都比旧版小。

求解后从整数归属重新提取公共边界，检查实际拐点总数与证书一致，并验证候选身份、成员、短弧、黄道及包络。导入文件按配方重算，不能通过修改证书字段获得“最优”标记。

### 5. 数值求解与失败处理

固定包装版本为 `highs-js 1.15.3`，内嵌求解器实际版本是 **HiGHS 1.15.1**，见 [来源、许可与指纹](../web/constellations/vendor/highs-1.15.3/README.md)。相对、绝对 MIP gap 都设为 0，整数可行性容差为 `1e−7`，并做整数解与几何后验检查。

这里的“已证最优”指浮点 MILP 求解器的最优性界与整数后验核对；没有另行导出可由精确算术独立复核的形式化证明文件。小网格另做穷举对照，避免仅检查求解器自己返回的字段。

求解在本地 Worker 内运行，双阶段共用 45 秒求解预算。超时、未证明最优、拓扑不合法或其他核验失败时，报错并保留当前轮次，不保存带最优标记的半成品。根种子的已求解边界缓存在当前会话中，局部重抽可复用；不保证所有种子和设备都在时限内完成。

## 正交边界与屏幕投影

“无斜边”按固定参考赤经／赤纬定义，和现代 IAU 区域沿参考赤道坐标划界的方向逻辑一致。本算法没有复制 IAU 的具体边界或声称复现历史划界过程。

工作台总览使用黄道坐标，局部图使用立体投影。赤经线、赤纬线投到这些图里可能倾斜或弯曲，投影也不会处处保留直角；这不意味着数据中加入了任意斜边。验证逐段检查 `RA₁ = RA₂` 或 `Dec₁ = Dec₂`，投影细分点不计入区域拐点。
