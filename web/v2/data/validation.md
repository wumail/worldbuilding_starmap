## 1. 为什么原画面容易显得过小

画面中的角度和屏幕实际占据眼前的角度，需要对应。把 60° 的天空放进眼前只占 20° 的窗口，同一轮月亮就会显得过小，即使相对天体的角径比例本身没有错。

设观看距离为 D 厘米，屏幕密度为 P 个 CSS 像素/厘米，则中心焦距 `F = D × P`。高 H 像素的窗口使用：

```
透视：垂直视场 = 2 atan(H / 2F)
立体：垂直视场 = 4 atan(H / 4F)
```

屏幕对角线与屏幕宽高比给出初步 P；页面的 5 厘米标尺允许手工校准，覆盖系统缩放等不确定性。改变窗口大小时保持 F、改变可见范围；滚轮改变共同倍率 g，使 `F显示 = gF`。恒星、行星、卫星与日面全部使用同一个 F。

关闭天体增强（1×）时，真实角直径仍为 `δ = 2 asin(R/Δ)`，R 是天体半径，Δ 是到中心的距离。透视画面中心的直径为 `2F tan(δ/2)`；立体投影为 `4F tan(δ/4)`。

地表 30°N、0°E、第 0 日：Luna 约 31.893′，Echo 约 6.874′，Sol 约 26.450′。例如 1920×1080、27 英寸 16:9 屏幕、60 厘米处，Luna 的几何盘面约 18 像素。实际值随显示器、浏览器缩放和观看距离改变。Echo 按设定只有 Luna 约 22% 的直径，不能为了显眼而画成同样大的实体。

透视对应从校准位置观看平面屏幕的几何；离轴圆呈椭圆是这种投影的正常结果，换天空盒不会消除。立体投影保留天球小圆的圆形，但离轴比例仍变。V2 平面页默认采用与 V1 一致的双半球方位等距总览，也可进入局部立体视图。总览是地图缩略图，保持 V1 的布局、底色、边框和地图操作，不能与局部 1× 混同。

## 2. 星等如何进入图像

V2 的校准局部视图不使用原版的星点符号半径曲线。双半球地图按用户要求复用 V1 的星点大小、亮度与采样核，并使用同样的默认 6 倍识读增强。以下光量模型用于校准视图及诊断；地图上的显示符号不冒充裸眼点像。

先用 V 波段/明视觉近似把视星等 m 换成观察者接收的照度：

```
E = 2.54 × 10⁻⁶ × 10⁻⁰·⁴ᵐ lux
```

差 5 等表示 100 倍总光量。背景星与未分辨行星用这一总光量生成点源；初始像素沉积采用归一化双线性权重。点源能量乘局部投影的像素/立体角比例，包含透视、立体及总览的面积变化。这是物理诊断缓冲的光量表示。最终点像使用解析高斯分布和亮度压缩；星等越亮，像素亮度和可辨识光点范围越大。这不表示恒星实体的直径。

Sol、可分辨的行星与两月由角径决定实体盘面。盘面立体角 `Ω = 4π sin²(δ/4)`，Sol 的均匀表面亮度近似为 `E/Ω`。反射体沿用世界观原有的 Lambert 球：

```
Φ(α) = [sin α + (π−α)cos α] / π
盘面峰值辐亮度 L峰 = E / [Ω × (2/3) × Φ(α)]
表面亮度 = L峰 × max(0, 法线 · 光照方向)
```

星等已经包含相位的总光量变化，所以这里除以 Φ，再由受光表面积分恢复它，避免重复扣除相位。这里的 Ω 与小视圆盘积分相配是小角近似，对当前不足一度的天体适用。显示中的星等仍适用于月亮，但星等本身不能代替角径。

实体盘面的暗区仍不透明。已分辨盘面从远到近绘制，轮廓按像素覆盖率抗锯齿。点源先在角空间中判断遮挡；未分辨天体部分露出时，按剩余受光面积计算光量和位置，然后沉积像素，避免被轮廓抗锯齿再次扣光。物理诊断缓冲在等效半径 1.2 设备像素附近选取积分方法；最终日月画面始终使用同一盘面覆盖路径，避免跨接口时光晕和大小突变。未分辨行星的点像与盘面采用连续过渡，轮廓仍不透明。部分重叠、极细月牙、升落边界仍有有限采样误差。

## 3. 轻微光扩散与屏幕亮度

本轮修复了两类与物理公式无关的显示错误：

- **饱和破坏边缘覆盖**：旧流程先把覆盖率 c 乘进极亮辐亮度 L，再做非线性映射 T，得到 `T(cL)`。即使只覆盖少量像素，太阳/月亮也能令它接近白色，形成硬台阶。现在盘面在子像素中映射亮度，再按覆盖率合成，采用 12×12 边缘采样；暗面仍覆盖后方天体。为保留月面层次，显示层先压缩表面峰值，再乘 Lambert 受光因子；物理诊断仍积分原始辐亮度。
- **截断核露出方形**：旧流程对 HDR 太阳做横竖有限高斯卷积，再提亮尾部，矩形支持域被显示出来。现在日月采用已压缩到屏幕范围的图像再做轻微扩散，尾部不再被高亮映射成方块。这是有意选择的显示近似，不能再称为严格的“所有 HDR 光量先卷积、后色调映射”。

光量保存在独立 32 位浮点缓冲中用于核验；该缓冲始终使用物理角径与物理遮挡，不受显示增益影响。最终局部视图与总览都可应用明确标注的天体显示倍率。最终画面分开处理：

1. 天光的物理模型决定消光和达标阈值。屏幕背景独立映射为暗蓝夜空：无月基底约 `#050911`，月光适度抬升，白昼渐变为蓝天。大气模型不会把整片夜空自动曝光为中灰。该底色是显示设计，不能直接反推物理亮度。
2. 日月先做几何覆盖、受光与不透明遮挡，再对显示图做轻微扩散。1× 时默认核心半高全宽 1.5′，外围标准差 2′、混合权重 1%；可关闭。显示增强同步扩大盘面及扩散范围。此处的 1% 是显示层混合权重，不等于对太阳真实光能的严格散射比例。
3. 背景恒星和未分辨行星采用解析圆形高斯点像，先展开点源，再压缩亮度。支持半径按当前光量扩展到低于屏幕量化阈值，避免截断方边；局部投影导数同时变换核的形状和归一化，避免离轴能量增大却仍套用中心大小的核。双半球接缝为邻侧补绘并分别裁剪。
4. 最后转为 sRGB。双半球地图的星点使用 V1 显示核与同样的 sRGB 混合规则，并按显示轮廓处理遮挡。两半球之外固定为 V1 的 `#03060d`，圆内外边界单独画出；星光和辅助轨迹不泄漏到图外。窄屏改为上下双半球。

像素重建的最低宽度是显示采样处理，不宣称是人眼散射。盘面扩散是屏幕空间近似，远离视轴、地平线或地图接缝时不等同于完整球面光学卷积；本轮并未实现视网膜或大气散射的完整仿真。关闭扩散可单独检查几何盘面。太阳实际亮度无法由普通显示器复现。

窗口改变后，即使底层像素宽高恰好不变，也必须更新 CSS 尺寸和 DPR；本轮修复了该缓存条件，防止旧投影尺度导致盘面被绘制包围框裁成方块。

## 4. 地表可见性

空气质量路径使用 Kasten–Young 形式：

```
X(h) = 1 / [sin(h) + 0.50572(h+6.07995)⁻¹·⁶³⁶⁴]
m地面 = m大气外 + kX
```

h 以度代入第二项，第一项按角度转弧度。默认 k=0.20 mag/airmass，只是可编辑的晴空假设。母星的 1.18 atm 气压不能单独确定气溶胶、天气和透明度。未计算大气折射。

天光由可编辑无月背景（默认 21.7 mag/arcsec²）、太阳高度驱动的经验昼夜项、两月散射项组成。月光使用 Krisciunas–Schaefer 的散射形状并按两月实际照度缩放；距月小于 10° 采用下限，不声称精确描述近月光环。天光与消光都在最终星等筛选之前计算。

暗夜裸眼阈值采用常见 SQM–NELM 近似 `7.93 − 5 log10(10^(4.316−SQM/5)+1)`，上限 6.5 等。白昼延用并限在 −4 等只是示意，不能当成白昼目标搜索、扩展源对比度或具体观察者的精确可见性预测。假设观察者已适应当前环境，没有数十分钟的暗适应过程。

9327 是完整背景星表数量，地表达标数不再等于它。第 0 日双月很亮，模型在全地平线上方筛出 104 颗背景星；第 0.54 日白昼为 0。后两项是当前近似参数的输出，不是地球或 Terrax 的已测观测事实，也不是画面像素能逐颗分辨的保证。全天质心方式关闭地平线和大气筛选，仍保留 9327 颗。

## 5. 来源与适用范围

以下网页已经实际查阅，支持建模方向；V2 没有宣称完整复现其软件或论文算法：

- [SR Research — Visual Angle Calculator](https://www.sr-research.com/visual-angle-calculator/)：像素、物理尺寸和观看距离，以及居中/离轴视觉角度的区分。
- [Stellarium — StelToneReproducer](https://stellarium.org/doc/head/classStelToneReproducer.html)：世界与屏幕的适应亮度应分开，HDR 场景需要亮度响应转换。
- [Stellarium — StelSkyDrawer](https://stellarium.org/doc/head/classStelSkyDrawer.html)：点源星等、扩展源表面亮度、视场与视觉适应分别处理。
- [Jensen 等 — A Physically-Based Nightsky Model, SIGGRAPH 2001](https://graphics.stanford.edu/~henrik/papers/nightsky/)：星位与辐射量、受光月面、大气和夜空组成的物理建模框架。本次查阅的是作者项目页和摘要。

空气质量、月光散射及 SQM–NELM 采用上述已明确写出的常见近似形式；本次没有逐篇复核这些经验模型的原始拟合数据，因此不将 V2 当作地球模型经 Terrax 气象校准后的结果。双高斯视觉核与夜间基调也没有做人眼实测标定。

轨道、世界观半径、Lambert 相函数和最大时长沿用原版，背景仍为原 9327 星表。尚未建模多体扰动、长期岁差进动、恒星自行、月食、行星环、月面纹理、银河弥散光、天气及月亮错觉。该版本适合观看和比较世界观中的天空，不是精密星历或完全复现裸眼的承诺。

## 7. 两版的天体显示大小

V1、V2 侧栏均有“天体显示大小”，默认 6×，范围 1–8×。相对于前一轮地图的 1.6×，线性显示尺寸提高至 3.75 倍。背景星与行星光点乘同一显示倍率；实体采用 `δ显示 = 2 atan(g × tan(δ真实/2))`，使切平面盘面直径乘 g。太阳柔光与显示遮挡沿用同一放大轮廓。平面和沉浸图共享该值；投影缩放再统一作用于所有天体。

这是明确的识读增强，1× 可恢复原尺度。真实半径、距离、轨道、角径、星等和相位读数保持原值；食象遮挡的显示轮廓在 g>1 时属于增强后的图形，不能当作真实食分。V2 平面总览、局部视图与沉浸天球共享自己的显示倍率，默认值与 V1 相同。V2 的“肉眼尺度 1×”同时恢复相机倍率与显示倍率；双半球复位只恢复构图，保留大小选择。

V1 自动保存的旧默认 1.6× 会升级到 6×，明确操作过滑块的用户选择保留；V2 旧记录只补充新的大小字段，不重置时间、地点、初值或光感设置。

V2 在两个独立场景中分别处理物理光量和增强画面。显示点像在两个方向乘同一倍率，并按面积补偿维持表面明亮程度；日月沿用原来的表面亮度，以免放大后反而变暗。完整暗面和前后遮挡使用显示轮廓。星等阈值、消光与月光环境仍由原始物理天空决定。物理缓冲逐像素不变，增强图像不用于读取真实食分。

## 8. 本轮整图修复

另修复了两项在实际页面中发现的问题：

- V2 加载星表前只画少量天体，绘图几何首次缓存了 1024 个实例的上限；扩容时只换数据未刷新该上限，导致界面计数完整而实际星点被截断。现在扩容时重建对应几何，容量足够后持续复用。新增“先画加载帧，再加载超过 1024 个星点”的真实像素回归。
- 远离视野的点源在透视接近 90° 时，局部投影导数曾被错误外推到整张画面。现在先按真实视野与点像角范围排除无交集的星点，避免巨大的离轴椭圆抬灰夜空。

本轮结果见 [尺寸与完整星表验收记录](./display_size_20260914/validation.json) 和 [调整前后整图对照](./display_size_20260914/comparison.png)。数值及文件保护检查 **58/58**、V2 图形与交互 **41/41**（271 组样本）、V1 图形 **38/38** 均通过。两个版本四个正式入口均已打开并截图检查。

1024×1024 复位样本在同一对比度门槛下，新预设两半球合计有 12,051 个亮像素，原 1.6× 预设为 231 个；这是像素数而非独立可辨认恒星数量。先绘少量对象、再加载 1,301 个星点的结果，与一开始就加载完整样本逐像素相同；扩容后不会逐帧重建几何。6× 模式和 1× 的物理缓冲差值为零，增强暗面遮星与远视野污染检查差值也为零。

完整 9,327 星表的 V2 总览另连续播放约 4 秒、121 帧；原有两页同步检查播放约 12 秒、363 帧。两页 PNG 导出成功，使用新缓存版本复查默认值为 6×。平面图仍按半球边界裁剪，跨天赤道的天体可能分布在两张半球图上；这与盈亏的明暗分界不同。

## 9. 平面太阳圆形与沉浸星点清晰度修复

用户反馈两版平面 Sol 呈椭圆、V2 沉浸背景失焦后，增加以下显示修正。默认 6×、原有观看倍率、星等、角径与轨道参数保留。本节更新了此前章节中有关太阳地图轮廓、增强点像与外围扩散的描述。

平面太阳的中心仍按方位等距投影定位，显示半径改为 `r = F tan(δ显示/2) sqrt(θ/sin θ)`，其中 `F = 半球半径/(π/2)`，θ 是太阳到所在半球天极的角距离。θ→0 时比例取 1。这保留原局部投影椭圆的面积，将其画成圆形地图符号；不是宣称方位等距投影本身保圆。两版太阳使用相同规则，太阳柔光、V2 日面遮星和轨迹裁剪共用该轮廓。越过赤道或地平线时，太阳仍按半球边界裁剪，可能在两张图上各出现一段圆弧。

地图显示不再用太阳原先的椭圆投影误挡圆外星点。被圆形日面遮住的背景点源不会产生漏到盘沿外的光尾；其余在太阳后方的点像按日面覆盖裁剪，前方行星按距离保留。盘面从远到近绘制，禁用不再适用于圆形太阳的角空间整盘剔除。物理诊断仍使用真实角径和原始球面投影遮挡。

上一轮四次指数核心仅收紧光斑边缘，仍把抗锯齿的固定像素宽度乘上了天体显示倍率。在用户的 0.22×、8×、88.3° 宽视野下，这会产生不随视野同比缩小的模糊光斑。该实现已替换，历史结果保存在 [上一轮验收记录](./round_sharp_20260914/validation.json)，不作为当前清晰度达标的证据。

目前 3× 以上的增强星点复用 V1 星等符号的大小、亮度及像素面积积分，半径为 `pointRadius(m) × F / F参考 × g`，所以星等、观看倍率 F 和增强倍率 g 各司其职。符号使用圆形边缘；未分辨恒星的显示符号不当作有实体轮廓的天体作离轴拉伸。抗锯齿按实际屏幕像素积分，不再乘增强倍率变成宽模糊核。大星点和 Canvas 参考均采用 16×16 子像素覆盖积分，小星点共用预积分纹理。1× 保留原 Gaussian 光学近似；1–3× 平滑过渡。增强星点保持清晰，光扩散开关仍控制日月及自然点像。

另将最终输出与物理采样分辨率分开：原四个 32 位浮点缓冲仍限制在约 220 万像素，用于物理诊断、天光和日月处理。需要时使用独立的原生分辨率 16 位浮点显示缓冲，先放置天光与日月，再直接绘制原生像素星点，最后统一转为 sRGB。不会再把星点随低分辨率图像交给 CSS 放大。显示输出采用最高 DPR 2、880 万像素上限；该上限之外仍会降采样，不宣称支持无限分辨率。

这是识读增强，不是新的人眼光学实测模型。去掉虚焦光尾后，星点的可见轮廓会比旧光斑紧凑；增强倍率、星等、真实角径、轨道和物理遮挡不变。当前验收直接与独立 V1 Canvas 输出逐像素对照，覆盖宽视野、星等、亚像素位置、DPR 1/1.5/1.75/2、物理分辨率上限两侧、缓冲复用释放及超过 1024 个实例的后加载星表；物理通量及原有日月遮挡检查继续保留。

当前结果和按用户参数复现的截图见 [原生清晰星点验收记录](./native_stars_20260914/validation.json) 与 [同视野修复前后对比](./native_stars_20260914/comparison.png)。第 6、8 节及上一轮圆形太阳的记录属于此前轮次，不能代替当前星点检查。
