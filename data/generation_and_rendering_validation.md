# 生成算法与图片映射验收

2026-09-13，生成器 / 图片导出器 4.3。

## 1. 至少 9000 颗的合同

默认成功输出必须同时满足：全天可见背景星 **9000–9500 颗**，每颗视星等 **m ≤6.5**，所有已实现物理关系和数量记账通过。生成结束与保存前分别检查实际星表，不能凭元数据中的“通过”标记跳过检查。

以 BSC5 校准的群体相对丰度为基础，将总体局部密度乘以 `9250/8404`，让无条件期望落在目标区间附近。每次完整生成盘状总体、抽取恒星参数并按亮度筛选；只有整份结果的数量符合闭区间才接受。每次使用 `SeedSequence(root_seed, spawn_key=(attempt_index,))` 的独立子流，默认最多 8 次，允许显式调整尝试预算。失败直接报错，资源预算或物理抽样错误也直接报错，不当作普通数量重试。

这不是固定 9000 个点，也不是从可见星中裁掉超额部分。设完整实现为 X，A 为 `9000≤N(X)≤9500`，p=P(A)，则首次接受结果的分布为：

`P(output∈B | 在8次内成功) = Σ(k=1..8)(1−p)^(k−1)P(X∈B) / [1−(1−p)^8] = P(X∈B | A)`。

因此保证的是**数量条件下的模型分布**；不宣称输出仍是无条件 Poisson 分布。根种子、每次子流、每次完整星数、接受序号、配置、代码和参考数据指纹全部保存。相同代码、配置、种子与 NumPy 版本可以重现。

24 个根种子（0–23）实测 **9080–9336 颗**，平均 **9197.21**，样本标准差 **69.55**，全部一次接受且物理检查通过。强制低于下限、高于上限以及耗尽次数的分支另有自动测试。[完整数量验收](count_contract_acceptance.json)

BSC5 原始目录严格按 Vmag≤6.5 有 **8404** 条有效恒星记录。新下限比该数高 7.1%，上限高 13.0%；这是满足“至少 9000”的世界设定选择，不再套用 8404±5%。这是全天目录数量，不是同一地面地点一晚可见的数量。

## 2. 总体生成和可见性计算为何成立

坐标以观测者为原点，+x 指向银心、+z 指向银北极。每个光谱型和演化阶段的总体密度为：

`ρ(x,y,z)=ρ_local exp[(R₀−sqrt((R₀−x)²+y²))/L + (|z₀|−|z₀+z|)/H]`。

这是一种轴对称双指数盘模型。不同群体采用不同尺度高度，观测者默认位于 R₀=8200 pc、z₀=20 pc。

在半径 h 的球壳内，`R≥max(0,R₀−h)`、`|Z|≥max(0,|z₀|−h)`，由这两个下界构造密度上界 ρ_max。以 `Poisson(ρ_max·4π(h³−r_min³)/3)` 抽候选数，分别均匀抽 r³、银经和 sin(银纬)，得到体积均匀的球壳候选；每点以 `ρ/ρ_max` 独立保留。这是标准 Poisson thinning，得到指定盘密度的总体。

随后在每个保留的空间位置上抽物理参数。主序星沿 Mamajek 2022.04.16 经验序列，在共同的 log(温度) 轴联合插值质量、光度和热光校正。亚型权重是 Kroupa 型 IMF 加近似存活时间的分段中点近似，并非精确 IMF 积分。演化星先抽取可行的温度和绝对星等，再在它们允许的质量区间均匀抽质量；这是分层经验模型，并非完整恒星演化轨道。物理提议失败时在**原位置**重抽，不因拒绝率而减少该群体的星数。

每颗星正向计算：

`m = M_V + 5 log10(d/10 pc) + A_V`，

`A_V = (k/1000) ∫₀ᵈ exp[(|z₀|−|z₀+s sin b|)/H_dust] ds`。

积分在穿越盘面处分段解析求值，近零倾角使用稳定的展开。独立数值积分测试覆盖正负高度、朝向/远离盘面、零纬度和盘面穿越；不以再次调用同一函数冒充独立验证。亮度筛选只发生在位置和物理参数确定之后，没有倒推目标距离或目标视星等。

为省去必不可见的体积，每类用其最亮可能 M_V 求**无消光可见地平线**。主序的 M_V 在每个插值段上为线性，最亮值必在参考节点；演化星由经验范围给出最亮端。消光非负，因此地平线外看不见任何该类恒星，省略它们不改变可见子集的分布。

算法保证限于配置的 **1–10000 pc** 背景球壳。总体抽样计数指各类可见地平线内实际抽到的星，不是整个星系的总数。宿主星及近距离伴星不在背景星表内。资源不足会失败，保证成功结果完整，不保证任意参数都能在预算内生成。

自动检查覆盖：球壳 Poisson 均值/方差、体积半径和方向分布、盘密度上界、逐类地平线、独立消光积分、单位和距离模数、热光零点、Stefan–Boltzmann 关系、主序关系、演化参数边界及总体/不可见/可见记账。

## 3. 可见星如何正确落到图片

导出器先验证新版星表，再按星表记录的极限星等筛选 `stars` 和 `neighbors`，记录排除项并拒绝重复 ID。银道字段通过右手正交矩阵转赤道坐标；仅有明确 RA/Dec 字段时直接使用。矩阵保持角距离和朝向。姿态沿用旧图的近似地球 J2000 定义（与常用标准矩阵约差1.72角分），黄赤交角25°；它是架空世界的固定约定，不冒充地球全精度天球定向。

北图包含 Dec≥0，南图包含 Dec<0。归属在双精度阶段决定，因此微小负赤纬不会因 GPU 舍入到负零而被错分。两张图采用天极中心的**方位等距投影**；赤道为图的坐标边界，极点在中心。这种投影保持到天极的角距离比例，并非全图保角或等面积。

令 N 为每个半球的像素边长，P 为符号余量，R=N/2−P，q=R(1−|Dec|/90)，a=RA−13.564125°，则半球图中的连续像素坐标为：

- 北：`x=N/2−q sin(a), y=N/2+q cos(a)`。
- 南：`x=N/2+q sin(a), y=N/2+q cos(a)`。

左上角为原点，像素中心为 `(列+0.5, 行+0.5)`。合并时南在左、北在右，统一增加外边距；北图 x 再加 N。归属与最终中心直接传入 GPU，不在 shader 里重复换算、翻转或分类。RA 的0/360°通过正弦余弦连续；网格线先在球面赤道处分段，再投影，不依赖方形视口裁出半球。

P 取最大星点半径向上取整再加2像素。因此最亮、最靠近赤道的星点也完整落在黑色圆盘内。坐标赤道内缩后留下的黑色环带是绘图余量，不代表额外天空；真实星位没有单独挪动。半球圆形遮罩采用对称边界。

符号直径在4K基准下为：`m≤4: 52−8m`；`m>4: 20exp[−0.536(m−4)]`，按分辨率缩放，最低 **2.5 px**。亮星的符号不会小于暗星；光晕在外缘平滑降到零。片元按实际像素中心到星心的距离计算，避免插值误差；最小符号也覆盖至少一个有明显非零贡献的像素。

片元使用 `10^(−0.4m)+0.6` 的显示增益、核心和光晕，并以RGB8加法混合。颜色为归一化光谱色相，默认白色。**这是符号图，不是相机曝光或肉眼生理模型；PNG不保留真实光通量比。** 亮度和大小映射为单调规则，饱和会使不同亮星相等；星点重叠可能形成同一个光点，不能声称9327颗必然是9327个可分别辨认的亮斑。

每次导出强制执行：

1. 逐星检查半球归属、完整符号的边缘余量、独立栅格计算中的非零像素贡献。
2. 实际读取 GPU 的纯星点层，用另一份 CPU 栅格计算逐像素比较；RGB8容差为2个码值，超差即拒绝保存。CPU参考不调用 shader，且GPU使用实际像素坐标计算。
3. 添加网格后确认没有降低星点层的任何通道；合并后保存到临时PNG，重新打开并逐像素比较两张半球与GPU场景原图（按数学圆形遮罩换算），再比较整张PNG与保存前图像。检查完整RGB颜色和符号，不能只凭见证亮点通过。通过后才写出新图片及报告，已有文件拒绝覆盖。
4. `.render.json` 记录输入/图片/导出代码指纹、阈值、被排除的ID、每颗星的方向、半球、连续中心、符号大小、检验像素、GPU及PNG验证结果。

独立测试包含固定方向锚点、两天极、赤道两侧、赤道零点、RA接缝、临界星等、重复ID、颜色、空星表、2K/4K成图、重开PNG和覆盖保护；另有121个像素相位的真实GPU暗星测试及固定位置的亮度/大小单调检查。[GPU验收记录](rendering_acceptance.json)
